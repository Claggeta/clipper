# Clipper v0.2.0

Second release. Clipper can now cut the clips it finds. Everything still runs
locally.

## What it does

`clipper render <video> <result.json>` reads the JSON that `clipper analyze`
saved, and writes one video file per candidate. Each clip is re-encoded
(`libx264`, `aac`, `yuv420p`) so the cut starts and ends where it was asked to
([ADR 0007](../decisions/0007-cut-clips-by-re-encoding.md)).

- Clips go to `data/clips/` (`CLIPPER_CLIPS_DIR`), named
  `<video name>_<HHMMSS>-<HHMMSS>.mp4`. Rendering the same candidate again
  overwrites the same file
  ([ADR 0008](../decisions/0008-clip-output-location-and-naming.md)).
- `--rank N` (repeatable) renders only the chosen ranks, where rank is the
  1-based position in the saved candidate list.
- `--captions` burns the transcript text into each clip, using one fixed style.
  Captions are built from segment-level text
  ([ADR 0010](../decisions/0010-burn-in-captions-from-segment-text.md)). A clip
  with no speech in range renders without captions and prints a note.
- Problems that can be found before cutting (a bad or missing JSON, a video
  whose name differs from the one analysed, a rank out of range, a candidate
  past the end of the video, no video stream) exit 1 with nothing written. If
  one clip fails while others succeed, the rest still render, then the command
  exits 1
  ([ADR 0009](../decisions/0009-render-reads-saved-json-and-probes-media.md),
  [ADR 0011](../decisions/0011-render-command-shape-and-failure-policy.md)).

`ffprobe` is needed as well as ffmpeg. It ships with ffmpeg.

Install from source. See the [README](../../README.md) for requirements, usage
and sample output.

## Also in this release

- The ffmpeg process helper is shared by the audio extractor and the renderer
  (#34).
- A fix to `test_clips_dir_default`, which failed in any shell that had
  `CLIPPER_CLIPS_DIR` set (#52).
- The caption builder removes `{ } < > \` from cue text. libass reads them as
  markup, and `\n` in particular swallowed a letter on screen (#48, #50, #54,
  [ADR 0010](../decisions/0010-burn-in-captions-from-segment-text.md)).
- The [manual test checklist](../manual-testing.md) now covers rendering
  (R0 to R14) and captions (C0 to C8) (#46, #53, #55).

## What was checked

CI runs ruff, mypy (strict) and pytest. It cannot run real ffmpeg, ffprobe or
Whisper, so the manual checklist was run on one setup: 2026-10-31, Windows 11,
PowerShell, ffmpeg `9.0.2-full_build-www.gyan.dev` (with libass), a 5:14 speech
video, Whisper `base` on CPU.

- Rendering, R0 to R14: every step behaved as documented. All 5 candidates
  rendered in 12.0 s as plain clips. Every clip was `h264`, `yuv420p` and `aac`,
  with a duration at most 0.028 s over the one requested.
- Captions, C0 to C8: `--captions` rendered the same 5 candidates in 12.05 s.
  The clips, the no-speech note, temporary-folder cleanup, paths with spaces and
  relative paths all behaved as documented. The maintainer reported that the
  caption frames looked good.
- `\n` in caption text was found by a check on generated media and fixed in
  this release (#54). The fix was first looked at on one frame of that media,
  by the assistant that wrote it. The maintainer then ran C7 on the merged code
  and saw `path C:newtable` in the `awk6.png` frame. The other C7 frames from
  that re-run were not reported.
- A real `--captions --rank 1 --rank 5` run on the 5:14 video, with output
  to `data\clips`, printed `Rendered 2 of 2 clips` (its exit code was not
  captured).

That is what was observed on that one setup, not a guarantee for other
platforms or ffmpeg builds. A build of ffmpeg without libass was not tried. The
caption style (`FontSize=18,Outline=2,Shadow=0,MarginV=30`) was looked at, not
tuned.

## Known limitations

- Captions need an ffmpeg build with libass. Without it every clip fails with
  ffmpeg's own message. There is no early check, and no build without libass
  was tried.
- Captions come from segment-level text. A long segment makes a large caption
  block, and a segment that crosses a clip edge shows its whole sentence for the
  part inside the clip. No cue on the 5:14 video was shorter than 0.5 s.
- The caption builder removes `{ } < > \`, so `5 > 3` shows as `5 3` and
  `C:\new` shows as `C:new`.
- A captioned clip has the same file name as a plain clip of the same span, so
  `--captions` overwrites an earlier plain clip, and the other way round.
- The source check compares file names only. A different video with the same
  name as the one analysed is cut without a warning
  ([ADR 0009](../decisions/0009-render-reads-saved-json-and-probes-media.md)).
  Two videos with the same name also overwrite each other's clips.
- A candidate that ends even slightly past the probed duration of the video
  fails the whole run.
- `render` has no `-v`, so only the 10-line ffmpeg failure message is
  available, not the full stderr.
- On Windows, ffmpeg exit codes are shown as unsigned 32-bit numbers, for
  example `4294967283` for a permission error. The error message itself is
  readable.
- The `render` message for a malformed JSON repeats the word "Invalid JSON".
- Long videos are unmeasured. Only the 5:14 video above has been timed.
- Everything from v0.1.0 still applies: weak signals on Whisper `base` output,
  and audio with no speech exits 0 with an empty table and a JSON file with no
  candidates.

## Pinned dependencies

Unchanged: `av==17.0.0` and `huggingface-hub<1.0`. See
[ADR 0003](../decisions/0003-pin-transcription-dependencies.md) before
unpinning either.

## Not in this release

Vertical reframing or cropping, caption styling beyond one default, word-level
captions, hardware encoders, concatenating clips, uploads, analytics, a web UI,
a database, user accounts, ML training, and any change to the detector.
