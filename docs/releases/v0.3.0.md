# Clipper v0.3.0

Third release. Clipper can now measure a detector against moments labeled by
hand, and has a second detector that asks a local LLM to score the transcript.
Everything still runs locally.

## What it does

`clipper eval <result.json>` reruns a detector on the transcript that
`clipper analyze` saved, so nothing is transcribed again, and compares its
candidates with a hand-written labels file
([ADR 0012](../decisions/0012-evaluate-detectors-against-hand-labels.md)).

- Labels files are JSON, one per video, read from `data/labels/`
  (`CLIPPER_LABELS_DIR`) by video name, or from a path given as the second
  argument. Times are `"M:SS"` or `"H:MM:SS"` strings. The format is in the
  [README](../../README.md#evaluating-detectors) (#63, #66).
- A candidate hits a label when they overlap by at least half of the shorter
  of the two. Recall counts labels with any hit. Precision is one-to-one: in
  rank order each candidate claims the first label it hits that no
  higher-ranked candidate has claimed, and one that hits only claimed labels is
  a repeat and does not count (#66, #76).
- Results are indicative: one labeler, a few videos.

`--detector heuristic|llm` on `analyze` and `eval` chooses the detector
([ADR 0013](../decisions/0013-choose-the-detector-with-a-cli-option.md)).
`heuristic` is the default. The saved JSON records the detector's name
(`heuristic`, or `llm:<model>`), and older JSON without it still loads (#72,
#80).

`--detector llm` scores every 45 s window the heuristic would score with a
model served by [Ollama](https://ollama.com), and keeps the best with the same
overlap rule
([ADR 0014](../decisions/0014-local-llm-detector-via-ollama.md)). Each
candidate's reason is the model's one-line reason.

- Settings: `CLIPPER_LLM_URL` (default `http://127.0.0.1:11434`) and
  `CLIPPER_LLM_MODEL` (default `qwen3.5:9b`). Ollama must be running with the
  model pulled (#79, #83).
- Requests ask for temperature 0, seed 0 and no thinking (`think: false`).
  With thinking, `qwen3.5:9b` took tens of seconds per window and ran out of
  context (#82).
- A server that cannot be reached, an HTTP error, a timeout or a reply that is
  not a valid score prints `Error: ...` and exits 1. It never falls back to the
  heuristic.

Install from source. See the [README](../../README.md) for requirements, usage
and sample output.

## Also in this release

- Windowing and overlap deduplication moved out of the heuristic into
  `adapters/detection/windows.py`, so both detectors score the same windows.
  Behaviour-neutral: the heuristic's output on the two saved analyses was
  byte-identical before and after (#74).
- File names and reasons are escaped in rich output. A yt-dlp name such as
  `Title [oFbD0Ot7nQ8].mp4` lost its video ID in table titles, and a reason
  containing `[/bold]` raised an error after the JSON was saved (#78).
- The `build_srt` docstring no longer raises a `SyntaxWarning` (#62).
- The [manual test checklist](../manual-testing.md) covers the LLM detector
  (L0 to L6) (#81).
- The README's `eval` sample shows one-to-one precision (#86).

## What was checked

CI runs ruff, mypy (strict) and pytest. It cannot run real ffmpeg, Whisper or
a model.

- LLM detector, L1 to L5, 2026-11-02: Windows 11, PowerShell 5.1, Ollama
  0.40.13, RTX 4070 Ti 12 GB, `qwen3.5:9b` and `llama3.1:8b`, both `100% GPU`.
  The results are in the
  [reference run](../manual-testing.md#llm-detector-reference-run) and ADR
  0014's model-choice amendment. On the short video, L1 took 19.5 s including
  the model load. `qwen3.5:9b` saved identical JSON on two runs (L3).
- ffmpeg, F1, 2026-11-02, on ffmpeg `9.0.2-full_build-www.gyan.dev`: with
  `-hide_banner -loglevel error`, the no-audio run printed
  `Output file does not contain any stream` and the invalid file printed
  `moov atom not found` and `Invalid data found when processing input`, with no
  banner. All four runs exited non-zero. Dependencies are unchanged since
  v0.2.0.
- `eval` on the two label files, at the default top 5 unless stated:

| Labels | Heuristic | `qwen3.5:9b` |
|---|---|---|
| `test_input.json` (5:14, 4 labels) | recall 3/4, precision 3/5, 2 repeats | recall 4/4, precision 4/5, 1 repeat |
| `oFbD0Ot7nQ8.json` (5:04:01, 30 labels), top 5 | recall 2/30, precision 2/5 | recall 0/30, precision 0/5 |
| `oFbD0Ot7nQ8.json`, top 30 | recall 5/30, precision 5/30, 2 repeats | recall 6/30, precision 6/30, in 953.4 s |

- `analyze` on the 5:04:01 stream: 20:59 cold on CPU with Whisper `base`,
  0.67 s with the transcript cached. One run (#69).

That is what was observed on one setup, not a guarantee for other machines,
models or Ollama versions.

## Known limitations

- **The LLM is not better at the top five.** On the long video its top five
  hit no label, against the heuristic's two, so `heuristic` stays the default.
- **LLM scores cluster on round values.** `qwen3.5:9b` used 11 distinct scores
  over 1,215 windows. Ties are broken by the earlier start.
- **The LLM is slow on long videos.** Every window is one request: 953.4 s for
  the 5:04:01 stream on the GPU above.
- **The labels are test examples.** Two files, one labeler, not a sample of
  the videos Clipper will be used on. Several long-video labels name visual
  moments, which a transcript-only detector cannot see. Whether that explains
  the LLM's misses is unverified.
- **The LLM only re-ranks fixed 45 s windows.** It cannot propose its own
  boundaries.
- **Repeatability is per model.** `llama3.1:8b` worded 2 of 6 reasons
  differently across two runs at temperature 0 and seed 0, with the same
  scores ([ADR 0015](../decisions/0015-determinism-is-per-detector.md)). The
  second long-video run of `qwen3.5:9b` (L5) was not done.
- **A reply cut off at the length limit** shows as `not a valid score ...
  (got '')` rather than saying it was cut off. Not seen since `think: false`.
- Everything from v0.2.0 still applies: weak heuristic signals on Whisper
  `base` output, segment-level captions in one style, no early libass check,
  name-only source check, no `-v` on `render`, and unsigned ffmpeg exit codes
  on Windows.

## Pinned dependencies

Unchanged: `av==17.0.0` and `huggingface-hub<1.0`. See
[ADR 0003](../decisions/0003-pin-transcription-dependencies.md) before
unpinning either. The Ollama client uses the standard library, so no
dependency was added.

## Not in this release

Downloading or URL ingestion, posting, analytics or platform metrics, a vector
database or retrieval, a trained neural network, audio or visual features, a
labeling UI, and any change to `render`. The Whisper experiment moved to V4.
