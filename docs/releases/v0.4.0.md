# Clipper v0.4.0

Fourth release. One command now takes a YouTube or Twitch URL, or a local
file, to a folder of post-ready drafts: 9:16 vertical clips with word-by-word
captions burned in, and a suggested title and hook for each. Which moments are
picked has not changed. Everything still runs locally and costs nothing.

## What it does

`clipper drafts <source>` fetches a URL or takes a file, analyses it, and
renders every candidate, ending with `Drafts: <folder>`
([ADR 0022](../decisions/0022-one-command-to-drafts.md), #108, #109, #110).
Vertical, captions and titles are on by default; `--no-vertical`,
`--no-captions` and `--no-titles` turn them off. A bad URL, a missing file or
an empty `CLIPPER_LLM_MODEL` stops it before anything is downloaded or
transcribed. Each step is still a command of its own:

- **`clipper fetch <url>`** downloads one YouTube video or Twitch VOD with the
  [yt-dlp](https://github.com/yt-dlp/yt-dlp) program to
  `data/videos/<id>.mp4` (`CLIPPER_VIDEOS_DIR`), at up to 1080p, and reuses a
  file already there. Playlist, channel, Twitch live and clip URLs are
  refused, and no cookies or logins are used
  ([ADR 0020](../decisions/0020-fetch-a-video-by-url.md), #103, #104).
  **Downloading from YouTube or Twitch is against their terms of service**,
  quoted in the ADR as read on 2026-11-03. Clipper is a personal tool, and the
  user is responsible for having the right to download a video.
- **`render --vertical`** makes 1080x1920 clips: the whole frame fitted to the
  width and centred on a blurred copy of itself. Nothing is cut off. An early
  centre crop cut off too much and was replaced before this release
  ([ADR 0016](../decisions/0016-vertical-centre-crop.md), #90, #92).
- **`render --captions`** now burns in styled captions a few words at a time,
  bold white with the word being spoken in yellow, laid out for the vertical
  or the source frame. They are built from word timestamps, which transcripts
  now record (`Segment.words`). An analysis saved by v0.3 has none, so its
  captions show whole segments, with a note
  ([ADR 0017](../decisions/0017-word-timestamps-and-styled-captions.md), #93,
  #95).
- **`render --titles`** asks the local model behind `--detector llm`
  (Ollama, `CLIPPER_LLM_MODEL`, default `qwen3.5:9b`) for a title and a hook
  per clip, from what is said in it. They are printed and written to the
  manifest, not drawn on the video. A title failure is that clip's failure;
  there is no fallback text
  ([ADR 0018](../decisions/0018-suggested-titles-via-ollama.md), #101).
- **A folder per video.** Clips go to `<clips dir>/<video name>/` with a
  `manifest.json`, replaced each run, that lists every selected clip with its
  span, score, reasons, file or error, captions, and title and hook
  ([ADR 0019](../decisions/0019-a-folder-per-video.md), #97).

Install from source. See the [README](../../README.md) for requirements and
usage. `fetch` and `drafts` with a URL need yt-dlp on `PATH`; titles need
Ollama running with the model pulled.

## Also in this release

- **Cached transcripts are made again once.** Transcripts now include word
  times, so the cache key changed and the first `analyze` of a video after
  upgrading transcribes it again. With word times, segments are split
  differently and some words change, so candidates can move slightly (ADR
  0017's item 3 amendment).
- The CLI's private factories were replaced by a context object,
  `AppContext` in `cli/context.py`, which tests pass doubles through. Its
  `--help` text was byte-identical before and after (ADR 0013's item 4b
  amendment, #99).
- The bodies of `analyze`, `render` and `fetch` moved into shared functions so
  `drafts` runs the same code. Behaviour-neutral, with every existing test
  unchanged (#109).
- **GPU transcription was measured and not adopted**
  ([ADR 0021](../decisions/0021-gpu-transcription-measured-not-adopted.md),
  #106). On the RTX 4070 Ti the 5:04:01 stream took 593 s against 1,260 s on
  the CPU, but the long transcript drifted from the CPU's and lost most of its
  punctuation, and the setup needs about 1 GB of NVIDIA packages. Transcription
  stays on the CPU.
- ADRs 0016 to 0022 record this release's decisions (#89 and the ADRs above).
- The [manual test checklist](../manual-testing.md) gained steps R15 to R19
  (vertical, the folder and manifest, titles), W9 (word timestamps), rewritten
  caption steps C2 and C7, and a Fetch section, D0 to D11.

## What was checked

CI runs ruff, mypy (strict) and pytest, 488 tests. It cannot run real ffmpeg,
Whisper, yt-dlp or a model. These manual runs were on one machine: Windows 11,
PowerShell 5.1, ffmpeg `9.0.2-full_build-www.gyan.dev`, Ollama 0.40.13 with
`qwen3.5:9b`, yt-dlp 2026.10.26, RTX 4070 Ti 12 GB. Most were run by the
assistant from the checklist's own commands in a separate process.

- **`drafts`, D8 to D10, 2026-11-03:** an 8:53 YouTube URL to 5 vertical,
  captioned, titled drafts in 71.5 s. The 5:04:01 stream from a local file,
  with a cold cache, in **22:58** (1,378 s), against 1,260 s for a cold
  `analyze` alone: vision criterion 5's long-stream time, timed once. With
  Ollama unreachable, every clip failed its title and nothing rendered (exit
  1); with `--no-titles` all 5 rendered.
- **`fetch`, D0 to D7:** a 7:54 YouTube video in 7.5 s (AV1 720p, its highest
  resolution) and a 7:32 Twitch VOD (H.264 1080p); a second fetch reused the
  file; the refused URLs, an unavailable video and a missing yt-dlp gave their
  messages; `analyze` read the fetched file. An AV1 source rendered
  `--vertical --captions` to H.264.
- **Titles, R19, 2026-11-03:** 5 of 5 clips titled on the 5:14 video, the same
  titles and hooks on a second run, and clear per-clip failures for a model
  that is not pulled and for an unreachable server.
- **Rendering and Captions sections, including R15 to R18, 2026-11-02:** the
  manifest listed the 5 clips in rank order with `captions: words`, a
  `--rank` run replaced it, and a constructed failure was listed with ffmpeg's
  message (ADR 0019). Vertical clips were 1080x1920 with SAR 1:1 for 16:9,
  9:16 and narrower sources (ADR 0016). Caption frames showed the expected
  chunk with the expected word in yellow, and no caption in a pause (ADR
  0017).
- **Word timestamps, W9:** no measurable time cost (14.7 s and 1,236.1 s cold,
  against 14.3 s and 1,260 s without), no segment without words, and words
  joined back into the segment text exactly.
- **ffmpeg, F1, 2026-11-03:** with `-hide_banner -loglevel error`, the
  no-audio run printed `Output file does not contain any stream` and the
  invalid file printed `moov atom not found` and `Invalid data found when
  processing input`, with no banner; the runs without the flags printed the
  banner. All four exited non-zero. Dependencies are unchanged since v0.3.0.

That is what was observed on one setup, not a guarantee for other machines,
builds or model versions.

## Known limitations

- **Which moments are picked is unchanged.** The heuristic is still the
  default, and its signals are still weak on Whisper `base` output. About half
  of the moments worth clipping are visual, and every detector reads only the
  transcript.
- **Titles are judged by eye.** Some run past the 60 characters asked for (up
  to 76 in the runs above, and a hook of 117), one inverted the speaker's
  point, and one hook repeated a swear word from the speech. Check them before
  posting.
- **With titles on and Ollama down, every clip fails** and nothing renders.
  The transcript is cached, so rerunning with Ollama up, or with
  `--no-titles`, is quick.
- **A long stream takes about 23 minutes** before its drafts are ready,
  nearly all of it CPU transcription (ADR 0021).
- **Letterboxed sources keep their bars** inside the fitted picture and in the
  blurred fill.
- **Caption style was chosen on one video.** A word that starts before a
  clip's first frame is not shown.
- **yt-dlp warns that no JavaScript runtime was found** on every YouTube
  request ("some formats may be missing"). Downloads worked in the runs above.
- **The manifest is replaced each run**, so a `--rank` run lists only the
  ranks it rendered. Two videos with the same file name share a folder.
- Still from earlier releases: no early libass check, a name-only source
  check, no `-v` on `render`, and unsigned ffmpeg exit codes on Windows.

## Pinned dependencies

Unchanged: `av==17.0.0` and `huggingface-hub<1.0`. See
[ADR 0003](../decisions/0003-pin-transcription-dependencies.md) before
unpinning either. yt-dlp is run as a separate program, not a Python
dependency, and no CUDA packages were added.

## Not in this release

Posting or uploads, analytics or platform metrics, campaign briefs, any change
to which moments are picked (detectors, windows, boundaries), audio or visual
detection features, subject or face tracking for the crop, hosted APIs or paid
services, web UI, database, user accounts, ML training, and GPU transcription.
