# 0015: Determinism is a property of the heuristic detector, not of every detector

- Status: Accepted
- Date: 2026-11-01
- Amends: `docs/vision.md`, success criterion 2

## Context

Success criterion 2 says detection is deterministic: the same transcript
always produces the same top 5. That holds for the heuristic, which is pure
arithmetic over the transcript. A local LLM (0014) is run at temperature 0 with
a fixed seed, which should make it repeatable on one setup. It is not a
guarantee across model versions, library versions or hardware, and no run has
checked it.

## Decision

1. Criterion 2 is restated per detector. The **heuristic** detector is
   deterministic, and a test keeps it so. The **LLM** detector is repeatable on
   one setup, as an aim, and not guaranteed.
2. The LLM adapter's PR measures repeatability on real transcripts: the same
   transcript run twice with the same model, and whether the top 5 matched.
   Whatever is seen is what is recorded, even if it is not a match.
3. `eval` runs a detector once per call. If the LLM turns out to vary between
   runs, repeat runs and a spread are added then, not before.
4. Saved results are the record. A saved `AnalysisResult` is not regenerated by
   `render`, which only reads it, so a non-repeatable detector does not make
   `render` unstable.

## Alternatives considered

- **Require determinism of every detector.** Rejected. It would rule out any
  LLM that cannot guarantee it.
- **Drop criterion 2.** Rejected. It is still true and still useful for the
  baseline.

## Consequences

- (+) The baseline stays reproducible, and the promise made to users stays
  true.
- (-) An LLM comparison on a single run can be noise. A difference between two
  detectors on a few videos is not evidence by itself (0012).

## Revisit when

- The LLM adapter's repeatability check shows run-to-run variation. Then add
  repeated runs to `eval`.
